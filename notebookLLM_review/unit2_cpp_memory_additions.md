## 1. מלכודת מבחן קריטית: בנאי העתקה מול אופרטור השמה

אחת השאלות הנפוצות ביותר בבחינות היא הבחנה מדויקת בין קריאה לבנאי העתקה לבין קריאה לאופרטור השמה:

```cpp
Person p1("Alice", 20);

// מקרה א': יצירת אובייקט חדש בלוק זיכרון חדש!
Person p2 = p1;      // קריאה לבנאי העתקה (Copy Constructor)
Person p3(p1);       // קריאה לבנאי העתקה (Copy Constructor)

// מקרה ב': אובייקט p4 כבר נוצר והוקצה מראש
Person p4("Bob", 25);
p4 = p1;             // קריאה לאופרטור השמה (Copy Assignment Operator)
```

### כלל הברזל למבחן:
* **הצהרה + השמה באותה שורה (`Person p2 = p1;`)** $\leftarrow$ **בנאי העתקה!** (נוצר זיכרון ואובייקט חדש, אין זיכרון ישן לשחרר).
* **השמה לתוך אובייקט שכבר היה קיים (`p4 = p1;`)** $\leftarrow$ **אופרטור השמה!** (חובה לשחרר זיכרון ישן לפני ההעתקה ולבדוק השמה עצמית).

## 2. כלל השלושה (Rule of Three) וכלל החמישה (Rule of Five)

אם מחלקה מנהלת משאב זיכרון דינמי (כגון מצביע המוקצה באמצעות `new`), הקומפיילר אינו יודע לשכפל או לשחרר אותו בצורה בטוחה. העתקת ברירת המחדל של הקומפיילר היא **העתקה רדודה (Shallow Copy)** – כלומר העתקת כתובת המצביע בלבד.

### התקלה בהעתקה רדודה:
1. שני אובייקטים מצביעים לאותו אזור זיכרון בערימה (Heap).
2. כשהאובייקט הראשון נהרס, המפרק שלו משחרר את הזיכרון (`delete[]`).
3. האובייקט השני נשאר עם **מצביע יתום (Dangling Pointer)**.
4. כשהאובייקט השני יתרסק/ייהרס, תתרחש שגיאת **Double Free** והקפאת תוכנית קטלנית.

### כלל השלושה (Rule of Three):
אם מימשתם אחד מבין השלושה הבאים – **חובה לממש את כולן באופן ידני**:
1. **מפרק (Destructor):** `~MyClass()`
2. **בנאי העתקה (Copy Constructor):** `MyClass(const MyClass& other)`
3. **אופרטור השמה (Copy Assignment Operator):** `MyClass& operator=(const MyClass& other)`

### כלל החמישה (Rule of Five - C++11):
כאשר נוסף מנגנון Rvalue References ו-Move Semantics, מתווספים שני רכיבים מטעמי ביצועים:
4. **Move Constructor:** `MyClass(MyClass&& other) noexcept`
5. **Move Assignment Operator:** `MyClass& operator=(MyClass&& other) noexcept`

## 3. בדיקת השמה עצמית (`Self-Assignment Check`)

במימוש אופרטור השמה, חובה לבצע בדיקה האם האובייקט מושם לעצמו (`a = a;`):

```cpp
MyBuffer& MyBuffer::operator=(const MyBuffer& other) {
    // 1. בדיקת השמה עצמית - קריטי במבחן!
    if (this == &other) {
        return *this; 
    }

    // 2. שחרור הזיכרון הישן של האובייקט הנוכחי
    delete[] m_data;

    // 3. הקצאה עמוקה (Deep Copy) של הזיכרון החדש
    m_size = other.m_size;
    m_data = new char[m_size];
    std::memcpy(m_data, other.m_data, m_size);

    // 4. החזרת הפניה לעצמנו (מאפשר שרשור a = b = c)
    return *this;
}
```

* **מה יקרה ללא הבדיקה?** במקרה של השמה עצמית (`a = a`), השורה `delete[] m_data;` תמחוק את הזיכרון של `other.m_data` (כי `this` ו-`other` הם אותו אובייקט!). לאחר מכן ננסה להעתיק מזיכרון שכבר שוחרר – מה שיוביל לקריסה או לדריסת זיכרון.

## 4. מפרק וירטואלי (Virtual Destructor) והורשה

### ⚠️ המלכודת במבחן:
כאשר משחררים מופע של מחלקה נגזרת (`Derived`) באמצעות מצביע ממחלקת הבסיס (`Base*`), **מפרק מחלקת הבסיס חייב להיות וירטואלי (`virtual ~Base()`)**!

```cpp
class Base {
public:
    virtual ~Base() { std::cout << "Base Destructor\n"; } // ✅ חובה במבחן!
};

class Derived : public Base {
private:

    int* data;
public:
    Derived() { data = new int[100]; }
    ~Derived() override { 
        delete[] data; 
        std::cout << "Derived Destructor\n"; 
    }
};

int main() {
    Base* ptr = new Derived();
    delete ptr; // ללא virtual ~Base(), המפרק של Derived לא ייקרא ויגרם Memory Leak!
}
```

## 5. ארגון האובייקט בזיכרון וטבלה וירטואלית (Vtable)

כאשר מחלקה כוללת לפחות פונקציה וירטואלית אחת (`virtual`):
1. הקומפיילר מייצר **טבלה וירטואלית (Vtable)** קבועה ברמת המחלקה, המכילה מצביעים לפונקציות הווירטואליות.
2. הקומפיילר משתיל מצביע סודי בשם **`vptr`** בראש הזיכרון של כל ממופע/אובייקט (בהיסט 0).
3. הקריאה לפונקציה הווירטואלית מתבצעת בזמן ריצה באופן דינמי: `object->vptr[index]()`.

### תרשים זיכרון של אובייקט C++ בזיכרון:
```text
+-----------------------+          +------------------------------+
|   Object Memory       |          |      Vtable (M_Class)        |
+-----------------------+          +------------------------------+
| vptr (4/8 Bytes) ---- |--------> | [0]: &M_Class::gainAccess()  |
| char name[100]        |          | [1]: &M_Class::denyAccess()  |
| int age               |          +------------------------------+
+-----------------------+
```

## 6. מצביעים חכמים ב-C++11 (Smart Pointers)
* **`std::unique_ptr<T>`:** הבעלות על המשאב היא בלעדית. אינו ניתן להעתקה (`CopyDisabled`), אלא להעברה בלבד באמצעות `std::move`.
* **`std::shared_ptr<T>`:** הבעלות משותפת. מנהל מונה הפניות (Reference Count). הזיכרון משוחרר כאשר המונה מגיע ל-0.
* **`std::weak_ptr<T>`:** מצביע בלתי שולט. משמש לשבירת מעגלי ההפניות (Cyclic Dependency) בין אובייקטים של `shared_ptr`.
