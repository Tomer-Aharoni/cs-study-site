## 1. מלכודת מבחן קריטית: בנאי העתקה מול אופרטור השמה

אחת השאלות הנפוצות ביותר בבחינות היא הבחנה בין קריאה לבנאי העתקה לבין קריאה לאופרטור השמה:

```cpp
Person p1("Alice", 20);

// מקרה א': יצירת אובייקט חדש!
Person p2 = p1;      // קריאה לבנאי העתקה (Copy Constructor)
Person p3(p1);       // קריאה לבנאי העתקה (Copy Constructor)

// מקרה ב': אובייקט p4 כבר נוצר מראש
Person p4("Bob", 25);
p4 = p1;             // קריאה לאופרטור השמה (Copy Assignment Operator)
```

### כלל הברזל למבחן:
* **הצהרה + העתקה באותה שורה (`Person p2 = p1;`)** $\leftarrow$ **בנאי העתקה!** (נוצר זיכרון ואובייקט חדש).
* **השמה לתוך אובייקט קיים שכבר הוגדר קודם (`p4 = p1;`)** $\leftarrow$ **אופרטור השמה!** (נדרש לשחרר זיכרון ישן לפני העתקה).

## 2. כלל השלושה (Rule of Three) וכלל החמישה (Rule of Five)

אם מחלקה מנהלת משאב זיכרון דינמי (כגון מצביע המוקצה באמצעות `new`), הקומפיילר אינו יודע לשכפל או לשחרר אותו בצורה בטוחה. העתקת ברירת המחדל של הקומפיילר היא **העתקה רדודה (Shallow Copy)** – כלומר העתקת כתובת המצביע בלבד.

### התקלה בהעתקה רדודה:
1. שני אובייקטים מצביעים לאותו האזור בזיכרון.
2. כשהאובייקט הראשון נהרס, השרשראות שלו משחררות את הזיכרון (`delete`).
3. האובייקט השני נשאר עם **מצביע יתום (Dangling Pointer)**.
4. כשהאובייקט השני יתרסק/ייהרס, תתרחש שגיאת **Double Free** והקפאת תוכנית.

### הכלל:
אם מימשתם אחד מבין השלושה הבאים – **חובה לממש את כולן באופן ידני**:
1. **מפרק (Destructor):** `~MyClass()`
2. **בנאי העתקה (Copy Constructor):** `MyClass(const MyClass& other)`
3. **אופרטור השמה (Copy Assignment Operator):** `MyClass& operator=(const MyClass& other)`

*ב-C++11 ומעלה (כלל החמישה), מתווספים גם Move Constructor (`MyClass(MyClass&& other) noexcept`) ו-Move Assignment Operator מטעמי ביצועים.*

## 3. בדיקת השמה עצמית (`Self-Assignment Check`)

במימוש אופרטור השמה, חובה לבצע בדיקה האם האובייקט מושם לעצמו (`a = a;`):

```cpp
MyBuffer& MyBuffer::operator=(const MyBuffer& other) {
    // 1. בדיקת השמה עצמית - קריטי במבחן!
    if (this == &other) {
        return *this; 
    }

    // 2. שחרור הזיכרון הישן של האובייקט הנוכחי
    delete[] m_data;

    // 3. הקצאה עמוקה (Deep Copy) של הזיכרון החדש
    m_size = other.m_size;
    m_data = new char[m_size];
    std::memcpy(m_data, other.m_data, m_size);

    // 4. החזרת הפניה לעצמנו (מאפשר שרשור a = b = c)
    return *this;
}
```

## 4. מפרק וירטואלי (Virtual Destructor) וזליגת זיכרון בירושה

שאלה קלאסית בבחינות (כמו 2021א מועד 74 שאלה 5):
כאשר מחזיקים מצביע של מחלקת אב (`Foo* f = new Bar(100);`) ומבצעים `delete f;`:
* **אם המפרק ב-`Foo` אינו וירטואלי (`virtual ~Foo()`):** ייקרא המפרק של `Foo` בלבד, והזיכרון שהוקצה במחלקת הבן (`Bar`) **לא ישתחרר** $\leftarrow$ **זליגת זיכרון!**
* **אם המפרק מוגדר כ-`virtual`:** ייקרא קודם המפרק של `Bar` ולאחר מכן המפרק של `Foo` בצורה תקינה.

## 5. תופעת חיתוך אובייקטים (Object Slicing) והימנעות ממנה

* **מהי התופעה?** כאשר מעבירים אובייקט יורש לפי ערך (by-value) לפונקציה המקבלת אובייקט מסוג מחלקת הבסיס (`void process(Base b)`).
* **מה קורה בזיכרון?** המידע והשדות המיוחדים של מחלקת הבן נחתכים, ורק החלק של מחלקת הבסיס מועתק.
* **פתרון דפנסיבי:** העברת אובייקטים **תמיד לפי הפניה או מצביע** (`void process(const Base& b)`).

---

## 6. בעיית היהלום (Diamond Problem) וירושה וירטואלית

כאשר מחלקה יורשת משתי מחלקות שאף הן יורשות מאותה מחלקת בסיס, מיוצרים שני עותקים כפולים של מחלקת הבסיס ברמת הזיכרון.
* **פתרון:** ירושה וירטואלית במחלקות הביניים:
  ```cpp
  class Sender : virtual public Thread { ... };
  class Receiver : virtual public Thread { ... };
  class Messenger : public Sender, public Receiver { ... };
  ```

## 7. ארגון האובייקט בזיכרון וטבלה וירטואלית (Vtable)

כאשר מחלקה כוללת לפחות פונקציה וירטואלית אחת (`virtual`):
1. הקומפיילר מייצר **טבלה וירטואלית (Vtable)** קבועה ברמת המחלקה, המכילה מצביעים לפונקציות הווירטואליות.
2. הקומפיילר משתיל מצביע סודי בשם **`vptr`** בראש הזיכרון של כל ממופע/אובייקט (בהיסט 0).
3. הקריאה לפונקציה הווירטואלית מתבצעת בזמן ריצה באופן דינמי: `object->vptr[index]()`.

### תרשים זיכרון של אובייקט C++ בזיכרון:
```text
+-----------------------+          +------------------------------+
|   Object Memory       |          |      Vtable (M_Class)        |
+-----------------------+          +------------------------------+
| vptr (4/8 Bytes) ---- |--------> | [0]: &M_Class::gainAccess()  |
| char name[100]        |          | [1]: &M_Class::denyAccess()  |
| int age               |          +------------------------------+
+-----------------------+
```
